# 每日更新与发布

公募和机构间项目均由GitHub Actions采集。`scripts/refresh_all.py`是联合入口，只有两类数据的官方分页、主键、来源时间和关联校验均通过后，才生成同一批次并写回正式数据。

## 采集与证据

- 两类项目共用交易所访问节流与重试；云端使用`curl-ipv4`，保留原HTTPS接口、请求参数、Referer及响应字节。curl是GitHub托管Ubuntu自带工具。
- `REITS_HTTP_TRANSPORT=curl-ipv4`可复现云端访问路径；未设置时使用Python标准库。传输方式及每次网络错误记录在Raw目录的`transport/requests.jsonl`，响应以SHA-256命名，不能用旧响应冒充当天采集。
- 原始响应位于`data/raw/daily_refresh/<batch>/`；清洗结果、字段保留核对和校验位于`workpapers/daily_refresh/<batch>/`；来源与输出哈希位于`data/source_manifest/daily_refresh/<batch>.json`。
- 某一类采集失败后仍检查另一类，保留诊断；正式数据继续保留上一批完整快照，同时记录本次失败。

## 手动核查与自动更新的分工

审核状态、申报日期、基金成立与上市信息来自新采集的交易所记录。首发和扩募按独立申报ID处理，扩募关联原基金；单独新购入不计入首发或扩募数量。

已接受的招募书、公告等研究字段按稳定ID保留。财务顾问、预测收益、资产清单等字段保留实际核查日期，不能因为当天更新清单而改成当天核查。机构间原始权益人、承销商由当天官方API补充字段级证据。`field_retention.json`核对原值、新值、证据和来源日期；清空已核实值或遗失同值证据会阻止发布。

新附件由公募采集器收录至项目文件列表；需要人工判断的PDF研究结论仍须按现有补录审核流程核实。

## 发布验收

项目动态由核验后的数据生成。涉及正式数据的集成测试从输入数据推导测试日期，不把测试时钟固定在某个历史日期；生产日期校验保持严格。

Pages构建记录具体提交SHA。发布任务从相同提交读取期望内容，下载网站两类项目数据、刷新状态、发改委数据与项目动态，逐文件核对SHA-256及联合批次。公募和动态同时验证页面实际加载的gzip文件。校验结果保存为`live-verification`云端产物，保留30天。

已发布的失败状态若没有变化，不重复部署；失败状态变化、新完整批次或项目动态变更仍触发发布。

## 判断自动运行是否成功

必须同时核对实际`event=schedule`运行、采集结果、联合批次、发布运行以及线上文件。push或手动触发的修复验证单独标记。定时表达式不能作为自动采集成功或8点准时完成的证据。
