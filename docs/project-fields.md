# 项目库字段范围

公募项目采用19项研究字段，机构间项目采用13项。列表提供核心字段与全部字段两种视图，详情和CSV保留完整字段；代码、官方项目ID、来源链接和分类依据继续保留。

## 公募REITs

业务类型只统计首发和扩募，扩募关联原基金。单独新购入不纳入申报数量；来源记录与附件保留在采集底稿及范围排除记录中，不能仅因“新购入”而改为扩募。已发行基金名录保持完整。

| 分组 | 字段 |
| --- | --- |
| 基本资料 | 序号、项目名称、首发/扩募、交易所、REITs类型、原始权益人/发起人、基金管理人、财务顾问 |
| 融资规模 | 拟发售金额（申报稿）、拟发售金额（反馈稿）、拟发售金额（询价稿）、发售金额、外部贷款金额 |
| 资产与收益 | 资产类型、底层资产、项目收益预测情况 |
| 进度与增信 | 项目状态、更新日期、担保补足情况 |

各版本拟发售金额分别记录，不用最终金额倒填早期版本。扩募融资、贷款、预测和支持安排归属于该次事件，不继承基金首发的数值。已发行基金视图的金额为首发口径，申报视图的金额为该次首发或扩募口径。

主体按原始权益人/发起人、基金管理人、专项计划管理人和财务顾问等具体角色分别记录，不单列“发行人”字段。核心列表直接展示原始权益人/发起人及基金管理人。基金视图使用首发主体，扩募视图使用该次申报主体。REITs类型采用基础设施REITs、商业不动产REITs制度分类，资产类型与权利性质分别保留。

收益预测保留指标、年份、年化标记及文件版本。担保补足保留责任主体、安排和适用条件。每项已补充字段附官方文件、发布日期及页码；API字段保留官方项目入口、核查时间与原始字段名。

缺失值分别记录为未披露、暂无法取得、待核实或不适用，并保留核查原因。未定位到字段或仅查阅部分正文的项目标为待核实。没有实际发行证据的机构间项目保持未知，不推定为未发行。

实际募集金额以正式募集结果或生效公告为依据，是否包含利息等口径保留在逐字段证据中。拟募集额与最终金额分别保存。基金视图的底层资产、收益预测及融资研究字段采用首发披露；扩募新增资产与融资只展示在对应扩募事件。

官方清单刷新与披露核查分别保留时间。定时刷新保留同一项目ID下已核验的研究字段，但当前审核状态与更新时间始终使用新清单。

补充链路由`collectors/enrich_public_sse.py`、`collectors/enrich_public_szse.py`和`collectors/enrich_institutional.py`生成来源候选，经`scripts/apply_official_enrichment.py`校验后生成站点数据。原始响应在`data/raw/enrichment/`，逐字段候选与审核在`workpapers/enrichment/`，输入与结果哈希在`data/source_manifest/enrichment/`。大型PDF按实际查阅对象保留HTTP字节范围、版本标识及哈希，覆盖页码在各来源底稿列示。

站点金额统一使用亿元。参考表的公募金额表头未显式注明单位，本次只采用字段范围；以后新增数值时记录来源原单位、币种及换算依据。

## 机构间REITs

序号、项目名称、项目状态、交易所、申报金额（亿元）、资产类型、底层资产、原始权益人/发起人、计划管理人、受理时间、通过时间、发行时间、是否已发行。

申报金额沿用交易所申报口径。受理、通过、发行和更新日期分别记录，更新日期不作为通过或发行日期。是否已发行使用是、否、待核实三种展示；审核通过不自动表示已发行。

## 配置与维护

- `config/project_field_scope.json`是字段名称、单位、类型、分组及核心列表范围的配置。
- `assets/project-field-catalog.js`从配置生成，`assets/project-fields.js`统一表格、详情和导出的映射与格式。
- 新字段以显式空值加入数据快照；采集刷新按稳定项目ID保留已核实研究字段，不改变源站采集时间。
- 本次仅提取参考工作簿的两行表头，没有导入任何项目业务数值。表头Raw、来源哈希、映射及字段迁移核对分别保存在`data/raw/field_scope/`、`data/source_manifest/field_scope/`和`workpapers/field_scope/`。

现存审核快照中的旧字段与证据保留用于追溯，不进入当前页面或CSV字段目录。参考工作簿原始表头按原顺序留存，生成展示目录时排除“发行人”，其余字段不发生列位移。
